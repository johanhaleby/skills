# Workshop

**Workshop** starts when the user asks for one (`/domain-storytelling workshop`, "run a
workshop", "interview me about this"), or when a plan hinges on a process nobody has
written down. Ask in this order, one topic at a time:

1. **Scope.** Coarse or fine-grained? AS-IS or TO-BE? Pure (no software) or digitalized?
2. **The trigger.** What starts this process, and what does "done" look like?
3. **The actors.** Who takes part? A person, a group, or a system.
4. **The typical case.** Walk the happy path sentence by sentence. Say each one back as a
   sentence and let the user correct it. This is the whole technique.
5. **What else can happen.** Only now. Variations, exceptions, the rare cases.

Never interview and draw at the same time. Get the typical case whole, render it, then
talk about what else can happen.

A workshop also writes `<title> - open questions.md` next to the images whenever anything
was left unresolved:

- **Assumptions.** What you assumed to draw the happy path, and what breaks if it is wrong.
- **Open questions.** One idea per question, never compound, most important first, with a
  blank line under each to answer into.
- **Alternatives noted, not modelled.** Candidates for their own story later.

Leave it out entirely when there is nothing to write. If a question needs a person who is
not in the session, say so and offer `/to-questionnaire`. If the user's own assumptions
look soft, offer `/grill-me` (or `/grilling`). Offer them by name and let the user run
them, since both are deliberately explicit-invocation-only.
